# Mock PI Server 设计与验收规格说明书

**文档版本：** v1.0
**项目代号：** Mock PI Server
**目标用途：** 测试具有 AVEVA / OSIsoft PI 数据源连接能力的客户端
**首选实现语言：** Python 3.11+
**首选框架：** FastAPI + Uvicorn
**运行环境：** Windows / Linux / Docker
**核心原则：** 模拟 PI Web API 的常用行为，不尝试重新实现 PI Data Archive 私有协议。

---

# 1. 项目背景

当前测试环境没有可用的真实 PI Data Archive / PI Web API Server。

待测试客户端可能具有以下一种或多种 PI 接入方式：

| 接入方式                     | 本项目支持程度             |
| ------------------------ | ------------------- |
| PI Web API / HTTP REST   | 完整 Mock 核心场景        |
| HTTPS PI Web API         | 支持                  |
| Basic Authentication     | 支持                  |
| 自定义 Token/Header         | 可配置支持               |
| AF SDK                   | 不直接支持               |
| PI SDK                   | 不直接支持               |
| PI API                   | 不直接支持               |
| PI Data Archive TCP 5450 | 不实现协议，仅做 TCP 网络故障模拟 |
| ODBC/JDBC                | 本期不支持               |

本项目的目标不是制造一个真正的 PI Server，而是构建一个：

> **行为可控、数据可控、错误可控、适合自动化测试的 PI Web API Mock Server。**

最终真实 PI 兼容性仍然需要使用真正的 PI Test Server 或正式 PI 环境验证。

---

# 2. 项目目标

系统需要满足三个主要目标。

## 2.1 功能模拟

允许测试客户端完成典型 PI Web API 操作：

* 获取 Server 信息
* 查询 PI Point / Tag
* 根据 WebId 查询 Tag
* 读取当前值 Snapshot
* 读取历史数据 Recorded Values
* 读取时间范围数据
* 写入当前值
* 写入批量数据
* 处理数字、字符串、布尔值等基本类型
* 返回 Good / Questionable / Substituted 等质量字段
* 模拟不存在的 Tag
* 模拟空数据

---

## 2.2 故障模拟

测试系统必须能够主动制造：

* HTTP 400
* HTTP 401
* HTTP 403
* HTTP 404
* HTTP 409
* HTTP 429
* HTTP 500
* HTTP 502
* HTTP 503
* 请求超时
* 响应延迟
* 连接中断
* 无效 JSON
* 返回字段缺失
* 数据类型错误
* 异常 Timestamp
* Bad Quality
* 历史数据乱序
* 重复 Timestamp
* 大量历史数据

---

## 2.3 自动化友好

系统必须能够通过管理 API 动态控制行为。

例如测试脚本能够执行：

```http
POST /mock/config
```

将 Server 修改为：

```json
{
  "delay_ms": 5000,
  "force_status": 500
}
```

然后执行客户端测试。

测试结束后：

```http
POST /mock/reset
```

恢复默认状态。

不得要求测试人员手动编辑数据库或者重启 Server。

---

# 3. 非目标

以下内容明确不属于本项目范围。

## 3.1 不实现真正 PI Data Archive

不得尝试完整实现：

```text
PI Data Archive :5450
```

的私有协议。

---

## 3.2 不声称完全兼容 PI

项目文档、日志、UI 中不得出现：

```text
Fully compatible with AVEVA PI
100% PI compatible
PI Server replacement
```

正确描述应为：

```text
PI Web API compatible mock for testing
```

或者：

```text
Mock implementation of selected PI Web API behavior
```

---

## 3.3 不实现真实 AF 数据模型

本期只模拟：

```text
PI Data Server
PI Point
Stream
Recorded Values
Current Value
```

不完整实现：

```text
AF Database
AF Element
AF Attribute
Event Frame
Asset Hierarchy
Analysis
Notification
```

后续如实际客户端需要，再单独扩展。

# 4. 总体架构

系统架构如下：

```text
                        ┌────────────────────────┐
                        │      Test Client       │
                        │                        │
                        │  被测试 PI 客户端软件   │
                        └───────────┬────────────┘
                                    │
                                  HTTP
                                  HTTPS
                                    │
                                    ▼
                  ┌──────────────────────────────────┐
                  │          Mock PI Server          │
                  │                                  │
                  │  ┌────────────────────────────┐ │
                  │  │ PI Web API Compatibility   │ │
                  │  └────────────────────────────┘ │
                  │                                  │
                  │  ┌────────────────────────────┐ │
                  │  │     Fault Injection        │ │
                  │  └────────────────────────────┘ │
                  │                                  │
                  │  ┌────────────────────────────┐ │
                  │  │     Data Repository        │ │
                  │  └────────────────────────────┘ │
                  │                                  │
                  │  ┌────────────────────────────┐ │
                  │  │     Mock Control API       │ │
                  │  └────────────────────────────┘ │
                  └───────────────┬──────────────────┘
                                  │
                              JSON / SQLite
```

同时提供独立 TCP Fault Server：

```text
Test Client
     │
     │ TCP
     ▼
Mock TCP Server :5450
     │
     ├── Accept then close
     ├── Accept then hang
     ├── Reset connection
     └── No response
```

TCP Server 只用于网络异常测试。

# 5. 技术选型

推荐：

```text
Python >= 3.11
FastAPI
Uvicorn
Pydantic
SQLite
pytest
httpx
Docker
```

默认不引入 Redis、PostgreSQL 等额外组件。

理由：

* 部署简单
* 测试机依赖少
* Agent 容易开发维护
* HTTP Mock 性能完全足够
* FastAPI 自带 OpenAPI
* pytest 易于构建验收测试

# 43. TCP close 模式

```text

  ↓
TCP connect
  ↓
Server accept
  ↓
立即 close
```

```text
Server disconnected
Connection lost
Reconnect
```

---

# 44. TCP hang 模式

流程：

```text
Client
  ↓
TCP connect
  ↓
Server accept
  ↓
不读取
不写数据
不关闭
```

```text
Read Timeout
Handshake Timeout
```

# 45. 明确禁止 TCP Fake PI

TCP 5450 模块不得返回自行猜测的 PI 协议数据。

```text
尝试伪造 PI handshake
尝试逆向实现未知 PI protocol
```

除非后续获得正式协议规范并创建独立项目。
